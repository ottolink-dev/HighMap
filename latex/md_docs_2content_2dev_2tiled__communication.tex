This document explains the architecture of the tiled communication system in High\+Map, how collective directives operate across execution modes, and how halo overlap buffers are synchronized during iterative simulations.\hypertarget{md_docs_2content_2dev_2tiled__communication_autotoc_md110}{}\doxysection{\texorpdfstring{1. Overview and Purpose}{1. Overview and Purpose}}\label{md_docs_2content_2dev_2tiled__communication_autotoc_md110}
Terrain processing algorithms operating on large spatial domains must frequently scale beyond available GPU VRAM or system RAM. High\+Map achieves out-\/of-\/core scalability through the {\ttfamily Virtual\+Array} container, which subdivides heightmaps into a regular grid of overlapping tiles.

While local kernel operations (e.\+g. stencil filters with radius smaller than halo) require only local neighborhood information, global and iterative algorithms require communication across tile boundaries\+:


\begin{DoxyItemize}
\item Global reductions (computing global minimum, maximum, volume, or convergence residuals).
\item Global unions (collecting feature points, active wavefronts, or sink lists).
\item Execution synchronization barriers.
\item Iterative boundary halo exchanges (diffusion, wave propagation, flooding, snow creep, viscous flow, Poisson solvers).
\end{DoxyItemize}

High\+Map provides an abstract communicator interface, {\ttfamily ICommunicator}, decoupling simulation code from the underlying concurrency model.\hypertarget{md_docs_2content_2dev_2tiled__communication_autotoc_md111}{}\doxysection{\texorpdfstring{2. Communicator Interface ({\ttfamily ICommunicator})}{2. Communicator Interface ({\ttfamily ICommunicator})}}\label{md_docs_2content_2dev_2tiled__communication_autotoc_md111}

\begin{DoxyItemize}
\item {\bfseries{{\ttfamily all\+\_\+reduce(local\+\_\+val, op)}}}\+: Aggregates a scalar across all tiles using {\ttfamily Reduce\+Op\+::\+Min}, {\ttfamily Reduce\+Op\+::\+Max}, or {\ttfamily Reduce\+Op\+::\+Sum}. Returns the identical aggregated value to all calling tiles.
\item {\bfseries{{\ttfamily all\+\_\+union(local\+\_\+vals)}}}\+: Gathers and combines lists of scalar items (such as active seeds or coordinates) across all tiles.
\item {\bfseries{{\ttfamily barrier()}}}\+: Blocks execution until all tiles in the current collective phase reach the synchronization point.
\item {\bfseries{{\ttfamily sync\+\_\+overlap\+\_\+buffers(local\+\_\+tile, region, op)}}}\+: Synchronizes seam buffers along tile overlaps using a selected {\ttfamily Sync\+Operation}.
\end{DoxyItemize}\hypertarget{md_docs_2content_2dev_2tiled__communication_autotoc_md113}{}\doxysubsection{\texorpdfstring{Overlap Synchronization Modes ({\ttfamily Sync\+Operation})}{Overlap Synchronization Modes ({\ttfamily Sync\+Operation})}}\label{md_docs_2content_2dev_2tiled__communication_autotoc_md113}

\begin{DoxyItemize}
\item {\bfseries{{\ttfamily Smooth\+Blend}}}\+: Blends overlapping cells smoothly using a quintic polynomial (\$C\texorpdfstring{$^\wedge$}{\string^}2\$ smoothstep). Used by diffusion, flow simulations, snow settling, and Poisson boundary relaxations to prevent sharp seam artifacts.
\item {\bfseries{{\ttfamily Average} / {\ttfamily Mean}}}\+: Computes the arithmetic mean between corresponding overlap cells.
\item {\bfseries{{\ttfamily Min}}}\+: Takes the element-\/wise minimum across overlapping regions. Used by distance transforms and geodesic propagation.
\item {\bfseries{{\ttfamily Max}}}\+: Takes the element-\/wise maximum across overlapping regions. Used by priority-\/flood depression filling, water elevation surfaces, and multi-\/sweep flow accumulation.
\item {\bfseries{{\ttfamily Sum}}}\+: Computes the element-\/wise sum across overlapping regions.
\item {\bfseries{{\ttfamily Copy\+First} / {\ttfamily Copy\+Second}}}\+: Directional copy from one tile to another along boundary interfaces.
\end{DoxyItemize}\hypertarget{md_docs_2content_2dev_2tiled__communication_autotoc_md114}{}\doxysection{\texorpdfstring{3. Execution Engines}{3. Execution Engines}}\label{md_docs_2content_2dev_2tiled__communication_autotoc_md114}
The communicator adapts dynamically to the compute configuration specified in {\ttfamily Compute\+Mode} and the underlying {\ttfamily Storage\+Mode}\+:\hypertarget{md_docs_2content_2dev_2tiled__communication_autotoc_md115}{}\doxysubsection{\texorpdfstring{Single-\/\+Array Mode ({\ttfamily Single\+Array\+Comm})}{Single-\/\+Array Mode ({\ttfamily Single\+Array\+Comm})}}\label{md_docs_2content_2dev_2tiled__communication_autotoc_md115}
When an algorithm is invoked directly on a monolithic {\ttfamily Array} without tiling, {\ttfamily Single\+Array\+Comm\+::instance()} serves as the default communicator\+:
\begin{DoxyItemize}
\item {\ttfamily size()} returns {\ttfamily 1}, and {\ttfamily rank()} returns {\ttfamily 0}.
\item {\ttfamily all\+\_\+reduce} returns the input scalar directly with zero overhead.
\item {\ttfamily all\+\_\+union} returns the input vector unchanged.
\item {\ttfamily barrier()} and {\ttfamily sync\+\_\+overlap\+\_\+buffers()} are immediate no-\/ops.
\end{DoxyItemize}

Algorithms written with communicator parameters incur zero memory or synchronization penalty when run monolithically.\hypertarget{md_docs_2content_2dev_2tiled__communication_autotoc_md116}{}\doxysubsection{\texorpdfstring{Multithreaded Distributed Mode ({\ttfamily Threaded\+Tile\+Comm})}{Multithreaded Distributed Mode ({\ttfamily Threaded\+Tile\+Comm})}}\label{md_docs_2content_2dev_2tiled__communication_autotoc_md116}
In {\ttfamily For\+Each\+Mode\+::\+VA\+\_\+\+DISTRIBUTED} when all tiles can reside in memory concurrently ({\ttfamily Storage\+Mode\+::\+VA\+\_\+\+RAM} or {\ttfamily Storage\+Mode\+::\+VA\+\_\+\+DISK\+\_\+\+LRU\+\_\+\+FULL}), tiles execute across worker threads with a 1-\/to-\/1 mapping between tiles and ranks\+:


\begin{DoxyEnumerate}
\item {\bfseries{Registration}}\+: Every thread registers its tile pointer and {\ttfamily Tile\+Region} in a shared {\ttfamily Threaded\+Collective\+State}.
\item {\bfseries{Barrier}}\+: Threads enter a condition-\/variable barrier waiting for all ranks to register.
\item {\bfseries{Seam Exchange}}\+: Rank 0 iterates through the horizontal (\$x\$) and vertical (\$y\$) tile seams, reading and writing the overlapping memory regions between neighboring {\ttfamily Array} buffers according to the requested {\ttfamily Sync\+Operation}.
\item {\bfseries{Resumption}}\+: A second barrier releases all threads once seam synchronization is complete.
\end{DoxyEnumerate}\hypertarget{md_docs_2content_2dev_2tiled__communication_autotoc_md117}{}\doxysubsection{\texorpdfstring{Out-\/of-\/\+Core Sequential Mode ({\ttfamily Sequential\+Tile\+Comm})}{Out-\/of-\/\+Core Sequential Mode ({\ttfamily Sequential\+Tile\+Comm})}}\label{md_docs_2content_2dev_2tiled__communication_autotoc_md117}
When memory constraints dictate strict out-\/of-\/core streaming ({\ttfamily Storage\+Mode\+::\+VA\+\_\+\+DISK\+\_\+\+LRU\+\_\+\+STREAM}, where unpinned tiles are immediately evicted to disk) or when {\ttfamily For\+Each\+Mode\+::\+VA\+\_\+\+SEQUENTIAL} is requested with a collective communicator, tiles cannot execute in parallel.

High\+Map implements a cooperative sequential scheduler ({\ttfamily Sequential\+Thread\+Scheduler}) paired with per-\/rank {\ttfamily Tile\+Proxy\+Comm} handles\+:


\begin{DoxyEnumerate}
\item {\bfseries{Cooperative Threads}}\+: Each tile rank runs inside an OS thread managed by {\ttfamily Sequential\+Thread\+Scheduler}. A turn-\/taking mutex/condition-\/variable lock ensures that {\bfseries{at most one tile thread executes at any instant}}.
\item {\bfseries{Staging Cache}}\+: When a tile calls {\ttfamily sync\+\_\+overlap\+\_\+buffers}, its updated contents are written to a temporary disk-\/backed {\ttfamily Virtual\+Array} ({\ttfamily sync\+\_\+va} configured with {\ttfamily Storage\+Mode\+::\+VA\+\_\+\+DISK\+\_\+\+LRU\+\_\+\+STREAM}), and its local {\ttfamily Array} vector is deallocated.
\item {\bfseries{Turn Passing}}\+: The active rank triggers {\ttfamily on\+\_\+suspend\+\_\+rank} (releasing and evicting input/output tiles to disk) and passes the execution turn to the next active rank in round-\/robin order.
\item {\bfseries{Global Seam Sweep}}\+: Once all active ranks arrive at the synchronization barrier, the scheduler executes {\ttfamily sync\+\_\+va-\/\texorpdfstring{$>$}{>}sync\+\_\+overlap\+\_\+buffers(op)}, pinning and releasing pairs of adjacent tiles on demand.
\item {\bfseries{Tile Resumption}}\+: Ranks wake up in sequence, invoke {\ttfamily on\+\_\+resume\+\_\+rank} to re-\/acquire their input/output tiles, and reload the synchronized tile data from {\ttfamily sync\+\_\+va}.
\item {\bfseries{Lifecycle \& Exception Safety}}\+: If a rank finishes early, {\ttfamily Sequential\+Thread\+Scheduler} decrements the active participant count so remaining ranks do not deadlock. If any rank throws an exception, the scheduler aborts all waiting ranks and rethrows the captured {\ttfamily std\+::exception\+\_\+ptr} on the main thread.
\end{DoxyEnumerate}

For non-\/cooperative single-\/pass sequential loops ({\ttfamily \doxylink{virtual__array_8inl_a248e8e1edddfcc281ea3ce1b2c69b944}{sequential\+\_\+tile\+\_\+loop}}), {\ttfamily Sequential\+Tile\+Comm} provides a lightweight fallback that stashes eastern and southern halo strips in memory to forward one-\/way boundary conditions to subsequent tiles in raster order.\hypertarget{md_docs_2content_2dev_2tiled__communication_autotoc_md118}{}\doxysection{\texorpdfstring{4. When two adjacent tiles \$\+T\+\_\+0\$ and \$\+T\+\_\+1\$ are placed side-\/by-\/side along the \$x\$-\/axis\+:

\item The right halo of \$\+T\+\_\+0\$ covers the left core edge of \$\+T\+\_\+1\$.

\end{DoxyItemize}

During {\ttfamily Smooth\+Blend} seam stitching, cells across the overlap \$\mbox{[}0, H)\$ are blended smoothly\+:

\$\$r = \textbackslash{}text\{smoothstep5\}\textbackslash{}left(\textbackslash{}frac\{p\}\{H -\/ 1\}\textbackslash{}right)\$\$

\$\$\textbackslash{}text\{value\}(p) = (1 -\/ r) \textbackslash{}cdot T\+\_\+0(p\+\_\+\{\textbackslash{}text\{buf\}\}) + r \textbackslash{}cdot T\+\_\+1(p)\$\$

Any {\ttfamily Array} buffer passed to {\ttfamily sync\+\_\+overlap\+\_\+buffers(local\+\_\+tile, region, op)} must match the full tile geometry described by {\ttfamily region.\+shape} (nominal tile size plus halo margins).\hypertarget{md_docs_2content_2dev_2tiled__communication_autotoc_md123}{}\doxysubsection{\texorpdfstring{Incompatibility with Nested Multiscale Pyramids}{Incompatibility with Nested Multiscale Pyramids}}\label{md_docs_2content_2dev_2tiled__communication_autotoc_md123}
Algorithms that construct internal resolution pyramids (such as multiscale filters or cascades that downsample local tiles to coarse shapes \$\+L\+\_\+i\$) must not propagate the outer {\ttfamily Tile\+Region} or {\ttfamily ICommunicator} into the coarse levels\+:


\begin{DoxyItemize}
\item The downsampled buffer \$z\+\_\+\{\textbackslash{}text\{coarse\}\}\$ has dimensions \$\+L\+\_\+i\$, whereas {\ttfamily region.\+shape} and {\ttfamily region.\+halo} correspond to the full tile resolution.
\item Seam indexing logic assumes halo margins and strides match {\ttfamily region.\+shape}. Invoking synchronization on a downsampled buffer would cause halo offsets to exceed array bounds.
\item In multiscale pipelines, intermediate coarse levels execute locally using {\ttfamily Tile\+Region\+::dummy()} and {\ttfamily Single\+Array\+Comm\+::instance()}, while the outer {\ttfamily Tile\+Region} and {\ttfamily ICommunicator} are passed only at the full-\/resolution level where buffer dimensions match {\ttfamily region.\+shape}.
