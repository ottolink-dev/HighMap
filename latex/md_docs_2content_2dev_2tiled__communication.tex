 This document explains the architecture of the tiled communication system in High\+Map, how collective directives operate across execution modes, and how halo overlap buffers are synchronized during iterative simulations.\hypertarget{md_docs_2content_2dev_2tiled__communication_autotoc_md110}{}\doxysection{\texorpdfstring{1. Overview and Purpose}{1. Overview and Purpose}}\label{md_docs_2content_2dev_2tiled__communication_autotoc_md110}
Terrain processing algorithms operating on large spatial domains must frequently scale beyond available GPU VRAM or system RAM. High\+Map achieves out-\/of-\/core scalability through the {\ttfamily Virtual\+Array} container, which subdivides heightmaps into a regular grid of overlapping tiles.

While local kernel operations (e.\+g. stencil filters with radius smaller than halo) require only local neighborhood information, global and iterative algorithms require communication across tile boundaries\+:


\begin{DoxyItemize}
\item Global reductions (computing global minimum, maximum, volume, or convergence residuals).
\item Global unions (collecting feature points, active wavefronts, or sink lists).
\item Execution synchronization barriers.
\item Iterative boundary halo exchanges (diffusion, wave propagation, flooding, snow creep, viscous flow, Poisson solvers).
\end{DoxyItemize}

High\+Map provides an abstract communicator interface, {\ttfamily ICommunicator}, decoupling simulation code from the underlying concurrency model.\hypertarget{md_docs_2content_2dev_2tiled__communication_autotoc_md111}{}\doxysection{\texorpdfstring{2. Algorithms written with communicator parameters incur zero memory or synchronization penalty when run monolithically.\hypertarget{md_docs_2content_2dev_2tiled__communication_autotoc_md116}{}\doxysubsection{\texorpdfstring{Multithreaded Distributed Mode ($<$tt$>$\+Threaded\+Tile\+Comm$<$/tt$>$)}{Multithreaded Distributed Mode (<tt>ThreadedTileComm</tt>)}}\label{md_docs_2content_2dev_2tiled__communication_autotoc_md116}
In {\ttfamily For\+Each\+Mode\+::\+VA\+\_\+\+DISTRIBUTED} when sufficient memory exists to hold all tiles simultaneously, tiles execute concurrently across a thread pool\+:


\begin{DoxyEnumerate}
\item {\bfseries{Registration}}\+: Every thread registers its tile pointer and {\ttfamily Tile\+Region} in a shared {\ttfamily Threaded\+Collective\+State}.
\item {\bfseries{Barrier}}\+: Threads enter a condition-\/variable barrier waiting for all ranks to register.
\item {\bfseries{Seam Exchange}}\+: Rank 0 iterates through the horizontal (\$x\$) and vertical (\$y\$) tile seams, reading and writing the overlapping memory regions between neighboring {\ttfamily Array} buffers according to the requested {\ttfamily Sync\+Operation}.
\item {\bfseries{Resumption}}\+: A second barrier releases all threads once seam synchronization is complete.
\end{DoxyEnumerate}\hypertarget{md_docs_2content_2dev_2tiled__communication_autotoc_md117}{}\doxysubsection{\texorpdfstring{Out-\/of-\/\+Core Sequential Mode ($<$tt$>$\+Sequential\+Tile\+Comm$<$/tt$>$)}{Out-of-Core Sequential Mode (<tt>SequentialTileComm</tt>)}}\label{md_docs_2content_2dev_2tiled__communication_autotoc_md117}
When memory constraints dictate strict out-\/of-\/core execution (e.\+g. {\ttfamily Storage\+Mode\+::\+VA\+\_\+\+DISK\+\_\+\+LRU\+\_\+\+MIN}, where at most 2 live tiles are kept in memory at any instant), threads cannot execute in parallel.

High\+Map implements a cooperative sequential scheduler ({\ttfamily Sequential\+Thread\+Scheduler})\+:


\begin{DoxyEnumerate}
\item {\bfseries{Tile Fibers}}\+: Each tile runs inside a cooperative thread. Exactly one tile executes at any time.
\item {\bfseries{Staging Cache}}\+: When a tile calls {\ttfamily sync\+\_\+overlap\+\_\+buffers}, its updated contents are flushed to a temporary disk-\/backed {\ttfamily Virtual\+Array} ({\ttfamily sync\+\_\+va}).
\item {\bfseries{Turn Passing}}\+: The active tile suspends, freeing its RAM tile allocation, and yields execution to the next rank in round-\/robin order.
\item {\bfseries{Global Seam Sweep}}\+: Once all tiles reach the synchronization point, the scheduler executes {\ttfamily sync\+\_\+va-\/\texorpdfstring{$>$}{>}sync\+\_\+overlap\+\_\+buffers(op)} using the low-\/memory 2-\/tile sliding window cache.
\item {\bfseries{Tile Resumption}}\+: Ranks wake up in sequence and reload the updated, synchronized tile data from {\ttfamily sync\+\_\+va}.
\end{DoxyEnumerate}

This mechanism guarantees strict adherence to low memory ceilings (e.\+g. maximum 2 live tiles) while preserving multi-\/pass synchronization consistency across the entire grid.\hypertarget{md_docs_2content_2dev_2tiled__communication_autotoc_md118}{}\doxysection{\texorpdfstring{4. When two adjacent tiles \$\+T\+\_\+0\$ and \$\+T\+\_\+1\$ are placed side-\/by-\/side along the \$x\$-\/axis\+:
\begin{DoxyItemize}
\item The right halo of \$\+T\+\_\+0\$ covers the left core edge of \$\+T\+\_\+1\$.
\item The left halo of \$\+T\+\_\+1\$ covers the right core edge of \$\+T\+\_\+0\$.
\item The total overlap width between \$\+T\+\_\+0\$ and \$\+T\+\_\+1\$ is \$2\+H\$.
\end{DoxyItemize}

During {\ttfamily Smooth\+Blend} seam stitching, cells across the overlap \$\mbox{[}0, H)\$ are blended smoothly\+:

\$\$r = \textbackslash{}text\{smoothstep5\}\textbackslash{}left(\textbackslash{}frac\{p\}\{H -\/ 1\}\textbackslash{}right)\$\$

\$\$\textbackslash{}text\{value\}(p) = (1 -\/ r) \textbackslash{}cdot T\+\_\+0(p\+\_\+\{\textbackslash{}text\{buf\}\}) + r \textbackslash{}cdot T\+\_\+1(p)\$\$

\item The downsampled buffer \$z\+\_\+\{\textbackslash{}text\{coarse\}\}\$ possesses dimensions \$\+L\+\_\+i\$, whereas {\ttfamily region.\+shape} and {\ttfamily region.\+halo} correspond to the full tile resolution.
\item Seam indexing logic assumes the halo margins and stride match {\ttfamily region.\+shape}. If invoked on a downsampled buffer, halo offsets exceed the array boundaries, leading to heap corruption.
\item Intermediate downsampled levels represent purely local approximations used to calculate local delta adjustments (e.\+g. coarse valley carving), and are not decomposed into valid global sub-\/domains.
\end{DoxyItemize}

\begin{DoxyItemize}

\item The active {\ttfamily Tile\+Region} and {\ttfamily ICommunicator} must only be passed to the final resolution level where the buffer dimensions match {\ttfamily region.\+shape}.
